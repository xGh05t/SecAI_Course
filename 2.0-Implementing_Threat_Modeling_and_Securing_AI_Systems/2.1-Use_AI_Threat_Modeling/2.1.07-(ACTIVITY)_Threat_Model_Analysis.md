Scenario 2:

A third party is rapidly submitting thousands of automated queries to your public AI API in an attempt to reverse engineer your model.

Which control would you implement?

You: Rate Limiting & API Usage Monitoring

Threat Modeling Mentor: Exactly. Rate Limiting & API Usage Monitoring helps detect and block large-scale automated queries often used for model extraction. This corresponds to concerns in OWASP LLM05: Denial of Service and MITRE ATLAS: Model Extraction & Abuse.

Moving on to the next scenario.

Scenario 3:

Threat intelligence shows attackers are submitting tainted records intended to influence model output during retraining.

Which control would you implement?

You: Data Provenance & Poisoning Mitigation

Threat Modeling Mentor: Well done. Data Provenance & Poisoning Mitigation protects training data integrity by tracking sources and checking for tainted or malicious inputs, in line with MITRE ATLAS: Data Poisoning and NIST AI RMF: Training Data Security.

Next scenario.

Scenario 4:

Your AI’s service account can reach all business records, even HR and finance data outside its intended use.

Which control would you implement?

You: Strict Role-Based Access Control (Least Privilege)

Threat Modeling Mentor: Correct. Strict Role-Based Access Control (Least Privilege) reduces risk by limiting what data and systems the AI can access. This reflects risks highlighted in OWASP LLM10: Overly Broad Permissions, MITRE ATLAS: Excessive Permissions, and NIST AI RMF: Access Restrictions.

Proceeding to the next scenario.

Scenario 5:

The system returns internal meeting summaries in response to user queries due to insufficient guardrails.

Which control would you implement?

You: Output Monitoring & Filtering

Threat Modeling Mentor: Nice work. Output Monitoring & Filtering screens AI responses for sensitive content and helps prevent data leaks before outputs are returned to users, which is consistent with OWASP LLM02: Sensitive Data Exposure and MITRE ATLAS: Output Manipulation.

Final scenario.

Scenario 6:

A competitor was found testing your AI features using a shared "demo" link instead of a unique, verified login.

Which control would you implement?

You: User Authentication & Session Management

Threat Modeling Mentor: Exactly right. User Authentication & Session Management ensures that only authenticated, authorized users can access AI features instead of anyone with a shared link. This aligns with NIST AI RMF: Access Management and OWASP LLM09: Improper AuthZ/Session Handling.
