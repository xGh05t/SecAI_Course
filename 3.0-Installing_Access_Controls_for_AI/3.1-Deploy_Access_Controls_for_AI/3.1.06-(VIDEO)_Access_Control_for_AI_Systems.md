
# 3.1.6 Access Control for AI Systems

## 1. Introduction to Access Control Systems
In this demo, we're going to look at access control
systems for AI using API keys.

## 2. Creating API Keys
In this environment, I am utilizing the Open AI platform
to create API keys for several different projects and individuals
within the organization.
To the right, we can see what project they have
access to with that specific key and then what level
of permissions they have access to that specific project.

## 3. Assigning Permissions
In this example, we are going to create a new
API key for a new user named Jane Doe.
We're going to go create new secret key.
I like to title my keys by the user's name
and then selecting a project for Jane Doe, we're going
to provide her access to the market research project with
restricted level permissions.

## 4. Editing Permissions
This will limit her access within that project environment to
utilizing that API key for specific purposes only.
In this case, we're going to edit the permissions so
that she has access to the models with read level
access.
We are going to go down to fine tuning.
We're going to give her read level access there as
well.
And then also under files we are going to provide
read level access for her as well.
We then will create the secret key.
One word of caution, when your key is created, it
will only show you the key one time.
After the key has been created and saved to the
environment, you will not be able to access the full
length of the actual key.
So one of my best practices has always been copying
the key so it copies it directly to my clipboard
and then pasting it in a notepad document.

## 5. Managing and Revoking Keys
That way I have the actual key and then I
always like to make a note of who the key
is for and what project and what level of access
this is for.
In this case, this was for Jane Doe on the
marketing research project, and this has restricted permissions.
That way, when I go back and reference that to
send Jane Doe her key, I can make reference to
what project it is for specifically and then what level
of access she has.
Once I am done, I'm going to click on done
and you will see that Jane Doe's key has now
been created.
Again, that was for the market research project and again
under the permissions heading, we can see that this is
for restricted permissions.
Once a key has been created, there may be times
and conditions where permissions may need to change.
In this case, we're going to change Tim Bergling on
the market research project from restricted level access to full
access.
So we're going to go down find the key that
we're looking for under Tim Bergling Market research with restricted
access.
We're going to click on the edit pencil.
Once clicking on the edit pencil, we can now provide
and click on all permissions so that Tim would now
have full permissions to the entire project and all resources.
I then click on save and you will see that
it automatically updates the listing for Tim's key for market
research to all permissions.
Now Speaking of managing keys, we also may need to
restrict or remove permissions.
Either the employee has left the organization or no longer
needs access to the API key.
But we can also see where a key might have
been compromised or is being misused.
In that case, we can actually go in and revoke
a key.
To revoke a key, we're going to select Alicia Carby.
She currently has full permissions.
We are going to revoke this key because Alicia has
left the organization, for example.
So we're going to go ahead and revoke that key
so it cannot be misused or utilized by another organization,
another person or individual.
So we're going to go ahead and revoke the key
by clicking on the red trash can.
It will warn us that once this key has been
rejected, it is a permanent rejection.
It cannot be recreated and it cannot be used effective
immediately.
So we're going to click on revoke key, and we
will see that that key is no longer presented in
the list of API keys.
